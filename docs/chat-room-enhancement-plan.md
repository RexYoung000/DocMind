# 聊天室增强开发规划

**版本**: v1.0 | **日期**: 2026-04-23 | **分支**: master + feature/teaching-research

---

## 1. 需求背景

当前聊天室 Agent 只在用户发消息时被动回复，缺乏自主讨论和角色间互动，用户交互感弱。
本规划旨在将聊天室从"一问一答"模式升级为**事件驱动的多轮自主讨论引擎**。

## 3. Phase 1: 核心引擎重构

**目标**: 将聊天室从被动响应升级为事件驱动的自主讨论系统

**预估工时**: 5-7 天

### 3.1 讨论模式系统

**需求**: 用户创建聊天室时选择讨论模式，不同模式决定 Agent 的活跃程度

| 模式 | Agent 行为 | 适用场景 | 预估 Token 消耗 |
|------|-----------|---------|----------------|
| 温和 | 用户发消息后 Agent 讨论 2-3 轮，然后安静 | 正常教研讨论 | 每条用户消息 ≈ 2-3 次 API 调用 |
| 活跃 | 温和 + 空闲 30-60s 后 Agent 自主抛话题 | 深度研讨 | 温和基础上每小时额外 2-4 次调用 |
| 热烈 | Agent 持续讨论，支持打岔/抢话效果 | 头脑风暴/碰撞 | 每条用户消息 ≈ 5-8 次 API 调用 |

**涉及改动**:

| 文件 | 改动 |
|------|------|
| `types/index.ts` | `ChatRoom` 新增 `discussionMode: 'mild' \| 'active' \| 'intense'` |
| `stores/chatStore.ts` | `createRoom` 支持传入 mode |
| `pages/chat/ChatListPage.tsx` | 新建模态框新增模式选择区域，展示消耗预估 |
| `pages/chat/ChatRoomPage.tsx` | 根据模式切换引擎行为 |

### 3.2 事件驱动对话引擎

**核心架构**: 将消息生成从"用户触发 → 串行回复"改为事件队列驱动

> 当前实现说明：早期方案中的 `Scheduler` / `Reactor` 文件拆分已被新的策略模块替代。运行时代码现在使用 `eventRouterV2.ts`、`turnPlanner.ts`、`contextAssembler.ts`、`runtimeGuards.ts` 和 `ChatRoomPage.tsx` 集成；旧 `scheduler.ts`、`reactor.ts` 已删除。

```
┌──────────────────────────────────────┐
│         ChatEngine (新文件)           │
│                                      │
│  Event Queue                         │
│  ├── UserMessageEvent                │
│  ├── AgentResponseEvent              │
│  ├── IdleTimeoutEvent                │
│  ├── RoleCollisionEvent              │
│  └── TopicTriggerEvent               │
│                                      │
│  Event Router + Turn Planner          │
│  ├── 识别事件并排序                   │
│  ├── 根据策略选择 Agent 与发言姿态      │
│  └── 控制每轮发言数量                  │
│                                      │
│  Runtime Guards                       │
│  ├── 组装分层上下文                   │
│  ├── 校验身份边界与重复内容            │
│  └── 记录策略日志                     │
└──────────────────────────────────────┘
```

**新增文件**:

| 文件 | 职责 |
|------|------|
| `services/chatEngine/events.ts` | 事件类型定义与工厂 |
| `services/chatEngine/eventRouterV2.ts` | 识别点名、文档、证据、困惑、冲突、议题推进等事件 |
| `services/chatEngine/turnPlanner.ts` | 根据事件、模式、身份能力选择发言角色和发言姿态 |
| `services/chatEngine/contextAssembler.ts` | 按上下文深度组装文档、评审、聊天和角色记忆 |
| `services/chatEngine/runtimeGuards.ts` | 运行时身份兜底和重复防护辅助 |
| `services/chatEngine/collisionDetector.ts` | 检测观点矛盾，触发角色碰撞 |
| `services/chatEngine/topicPool.ts` | 从文档/评审结果中提取讨论话题 |

### 3.3 Agent 间回应链

**需求**: Agent 不仅是回复用户，还会回应其他 Agent 的观点

**实现逻辑**:

1. **观点提取**: Agent 回复后，从回复中提取关键观点标签（如 `agree:周老师`, `disagree:导入环节`, `question:教学目标`）
2. **回应决策**: 后续 Agent 生成时，prompt 中注入"当前讨论中其他 Agent 的观点摘要"，引导其回应
3. **回应链深度控制**:
   - 温和模式: 最多 2 轮 Agent 间互动
   - 活跃模式: 最多 3 轮
   - 热烈模式: 最多 5 轮
4. **自然中断**: 如果连续 2 个 Agent 表示同意无新观点，自动结束本轮讨论

**Prompt 模板变更**:

```
// 现有
"你正在群聊中，简短回复，像微信群聊，2-5 句。"

// 改为
"你正在教研讨论群聊中。
【当前讨论状态】
{discussionState}

【其他参与者观点】
{otherAgentViews}

【回应指引】
- 如果你同意某位老师的观点，请补充具体理由或案例
- 如果你不同意，请明确指出哪里不同意并给出你的方案
- 可以引用其他参与者的话并回应
- 保持你的角色人设，从{角色}角度出发

简短回复，像真实教研讨论，3-6 句。"
```

### 3.4 角色碰撞事件系统

**需求**: 系统偶尔触发角色间的立场碰撞，制造有价值的讨论冲突

**碰撞场景设计**:

| 碰撞类型 | 触发条件 | 示例 |
|---------|---------|------|
| 立场冲突 | 老师 vs 家长对同一观点有分歧 | 老师认为作业量合理，家长觉得太多 |
| 代际差异 | 学生 vs 老师对教学方法有不同理解 | 老师觉得板书重要，学生希望更多互动 |
| 专业分歧 | 两个老师关注不同维度的结论相反 | 一个认为目标偏高，另一个认为适中 |
| 价值观碰撞 | 家长内部对教育理念的根本分歧 | 虎妈型 vs 放养型 |

**实现方式**:

1. `collisionDetector.ts` 分析最近 5 条消息，检测是否有对立观点
2. 若检测到潜在碰撞，生成 `RoleCollisionEvent`
3. 调度器根据模式决定是否触发：
   - 温和: 不主动触发，仅被动检测
   - 活跃: 20% 概率触发碰撞事件
   - 热烈: 40% 概率触发
4. 碰撞事件会让相关角色 Agent 针锋相对 2-3 轮
5. 最终由"主持人"角色（或用户）收束讨论

### 3.5 打字指示器

**需求**: 显示 "周老师正在输入..." 增强实时感

**实现**:

| 文件 | 改动 |
|------|------|
| `types/index.ts` | 新增 `typingAgents: string[]` 到 ChatRoom 或组件 state |
| `pages/chat/ChatRoomPage.tsx` | 消息列表底部新增 TypingIndicator 组件 |
| `pages/chat/ChatRoomPage.tsx` | Agent 开始生成前设置 typing 状态，完成后清除 |

**视觉效果**:
- 显示 Agent 头像 + 名字 + "正在输入..." + 三个跳动的点动画
- 同时只显示一个 Agent 的打字状态（模拟真实聊天）
- 打字到消息出现的延迟：800-2000ms

### 3.6 Token 消耗提示

**需求**: 创建聊天室选择模式时，展示该模式下的预估 Token 消耗

**UI 设计**:
- 模式选择卡片中，每张卡片底部显示预估信息
- 格式: "预估消耗: 每条消息约 X 次 API 调用 | 每小时约 Y 次"
- 用浅色小字显示，不打扰主流程

## 4. Phase 2: 输入体验增强

**目标**: 提升输入效率和消息表达能力

**预估工时**: 3-4 天

### 4.1 斜杠命令菜单

**需求**: 输入 `/` 弹出命令菜单，快捷触发特殊操作

| 命令 | 功能 | 对应操作 |
|------|------|---------|
| `/vote` | 发起投票 | 弹出投票配置弹窗 |
| `/event` | 触发角色事件 | 随机触发一个碰撞事件 |
| `/summary` | 生成本轮讨论总结 | 调用总结生成 |
| `/doc` | 插入已上传文档 | 弹出文档选择器 |
| `/quote` | 引用评审维度 | 弹出维度卡片选择 |
| `/collect` | 收藏当前讨论焦点 | 保存到收藏夹 |

**实现**:
- 输入框 `onChange` 检测 `/` 开头，弹出浮动菜单
- 菜单支持键盘上下选择 + 回车确认
- 命令执行后可能打开二级弹窗或直接插入内容

### 4.2 快捷工具栏

**需求**: 输入框上方显示快捷操作按钮

**布局**:
```
┌─────────────────────────────────────┐
│ 📎文档  📋引用  ⭐收藏  🗳投票  🎲事件 │ ← 快捷工具栏
├─────────────────────────────────────┤
│ 输入消息...                    @ 发送 │ ← 输入框
└─────────────────────────────────────┘
```

| 按钮 | 功能 |
|------|------|
| 📎 文档 | 弹出已上传文档列表，选择后作为附件发送 |
| 📋 引用 | 选择评审维度卡片或历史消息进行引用 |
| ⭐ 收藏 | 收藏当前讨论中的某条消息 |
| 🗳 投票 | 快速发起一个投票 |
| 🎲 事件 | 随机触发一个角色事件 |

### 4.3 消息引用回复

**需求**: 点击消息可以引用回复，类似微信/飞书的回复功能

**UI 效果**:
```
┌──────────────────────────┐
│ ┃ 周老师 14:32            │ ← 被引用的消息（缩略）
│ ┃ "导入环节用情景模拟..."  │
│ ┌──────────────────────┐ │
│ │ 我觉得这个想法不错...   │ │ ← 回复内容
│ └──────────────────────┘ │
└──────────────────────────┘
```

**实现**:
- 每条消息 hover 显示"回复"按钮
- 点击后输入框上方出现引用条（可关闭）
- 发送时 `ChatMessage` 新增 `replyTo: string`（被引用消息 ID）
- 渲染时显示引用的消息缩略，点击可跳转

### 4.4 快捷发送已上传文档

**需求**: 从输入框旁快速选择已上传文档发送到聊天

**流程**:
1. 点击 📎 按钮或输入 `/doc`
2. 弹出文档选择弹窗（列表形式，显示文档名+上传时间）
3. 选择后，文档作为"附件消息"发送到聊天
4. 附件消息显示文档卡片（名称 + 类型图标 + 内容摘要前 100 字）
5. Agent 看到附件后会阅读文档内容并给出观点

**类型变更**:
```typescript
// ChatMessage 新增
attachment?: {
  type: 'document' | 'review_dimension'
  id: string           // 文档 ID 或评审 ID
  title: string        // 显示标题
  summary?: string     // 摘要
}
```

### 4.5 消息发送状态

**需求**: 用户消息显示发送中/已送达状态

**状态流转**:
```
sending → sent → delivered
              ↘ failed
```

**UI**:
- sending: 消息右侧显示加载 spinner
- sent: 显示 ✓
- delivered: 显示 ✓✓
- failed: 显示 ⚠ 点击可重试

**类型变更**:
```typescript
// ChatMessage 新增
status?: 'sending' | 'sent' | 'delivered' | 'failed'
```

## 5. Phase 3: 互动功能层

**目标**: 增强聊天的互动感和参与感

**预估工时**: 4-5 天

### 5.1 消息反应 Emoji

**需求**: Agent 和用户可以对消息做出 Emoji 反应

**支持的 Emoji**:
- 👍 赞同
- 👎 不赞同
- 💡 有启发
- 🤔 值得思考
- 😄 有趣
- ❤️ 喜欢

**实现**:

```typescript
// ChatMessage 新增
reactions: Array<{
  emoji: string
  userId: string    // 用户 ID 或 agent ID
  timestamp: number
}>
```

**Agent 自动反应**:
- Agent 回复时，对相关的前置消息自动添加反应（概率 40%）
- 例如: Agent B 不同意 Agent A 的观点 → 给 A 的消息加 👎
- Agent A 觉得用户提出好问题 → 给用户消息加 💡

**用户交互**:
- 消息 hover 显示反应条
- 点击选择 emoji 添加反应
- 已有反应显示 emoji + 计数，可再次点击取消

### 5.2 投票机制

**需求**: 用户或 Agent 可发起投票

**类型定义**:
```typescript
interface ChatPoll {
  id: string
  roomId: string
  messageId: string           // 关联的投票发起消息
  question: string            // "关于导入环节，大家觉得哪种方式更好？"
  options: Array<{
    text: string              // "情景模拟"
    voters: string[]          // 投票者 ID 列表
  }>
  createdBy: string           // 发起者（用户或 Agent）
  createdAt: number
  closed: boolean
  closeAt?: number            // 自动关闭时间
}
```

**投票流程**:
1. 用户点击 🗳 或输入 `/vote` → 弹出投票配置（问题 + 2-4 个选项）
2. 投票卡片作为特殊消息发送到聊天
3. Agent 根据角色人设自动投票（带延迟，800-2000ms 间隔）
4. Agent 投票后可附带一句话解释
5. 投票卡片实时更新各选项票数和比例条

**Agent 发起投票**（热烈模式）:
- 角色事件触发器可以触发 Agent 发起投票
- 例如: "小明: 老师们觉得课后作业多不多？我投'太多了'一票！"
- Agent 自动创建投票 + 投出第一票

### 5.3 @提及通知提醒

**需求**: Agent 在讨论中 @用户时，显示通知提醒

**通知形式**:
- 聊天室顶部弹出 toast 通知: "周老师 在讨论中提到了你"
- 如果用户不在聊天室页面（未来扩展），浏览器通知
- 通知可点击跳转到对应消息

**实现**:
- Agent 生成回复时，检测 prompt 引导其 @用户
- 消息渲染时，`@用户` 部分高亮显示
- 组件监听新消息，检测是否包含 `@当前用户`

### 5.4 讨论动态状态栏

**需求**: 聊天室顶部显示实时讨论状态

**显示内容**:
```
┌─────────────────────────────────────────┐
│ 🔴 3 位老师正在讨论「导入环节设计」        │
│ 已讨论 12 分钟 · 28 条消息 · 3 个观点分歧 │
└─────────────────────────────────────────┘
```

**状态栏信息**:
- 当前讨论主题（从最近消息中提取）
- 参与 Agent 数量和在线状态
- 讨论时长
- 消息数量
- 观点分歧数量

**实现**:
- 新增 `ChatRoomStatusBar` 组件
- 从消息历史中实时计算统计数据
- 讨论主题通过关键词提取或 LLM 小模型判断

## 6. Phase 4: 内容管理

**目标**: 讨论内容可追溯、可沉淀

**预估工时**: 3-4 天

### 6.1 聊天记录搜索

**需求**: 搜索历史消息，快速定位讨论内容

**搜索功能**:
- 顶部搜索框，支持关键词搜索
- 搜索结果高亮关键词，按时间排序
- 点击结果跳转到对应消息上下文
- 支持按 Agent 筛选（只看某 Agent 的消息）
- 支持按消息类型筛选（只看投票/只看附件/只看总结）

**UI**:
- 聊天室顶部工具栏新增搜索图标
- 点击展开搜索面板（覆盖消息列表上半部分）
- 实时搜索，输入即显示结果

### 6.2 观点收藏与导出

**需求**: 重要观点可收藏，最后汇总导出

**收藏功能**:
- 每条消息 hover 显示 ⭐ 收藏按钮
- 已收藏消息在侧栏"收藏"面板中列出
- 收藏时可添加备注

**导出格式**:
- Markdown: 按时间线列出收藏消息
- 结构化: 按话题分组，含 Agent 观点和标签
- 复制到剪贴板: 一键复制单条消息

**类型定义**:
```typescript
interface Bookmark {
  id: string
  roomId: string
  messageId: string
  note?: string           // 用户备注
  tags?: string[]         // 标签
  createdAt: number
}
```

### 6.3 讨论总结卡片

**需求**: 讨论告一段落后自动生成总结

**触发条件**:
- 温和模式: 用户手动触发（`/summary` 命令）
- 活跃模式: 每 15 条消息自动提示"是否生成总结"
- 热烈模式: 每 20 条消息或讨论暂停 2 分钟后自动生成

**总结卡片内容**:
```
┌──────────────────────────────────┐
│ 📋 本轮讨论总结                    │
├──────────────────────────────────┤
│ 🔑 关键共识 (3)                    │
│  · 导入环节建议改为情景模拟         │
│  · 教学目标需要拆分为 3 个子目标    │
│  · 知识链衔接需要强化过渡           │
│                                  │
│ ⚡ 主要分歧 (2)                    │
│  · 课后作业量：周老师适中 vs 刘妈妈过多│
│  · 重点讲解：陈老师详讲 vs 小明希望简洁│
│                                  │
│ 💡 待深入话题 (1)                  │
│  · 学习梯度如何适配不同水平学生      │
│                                  │
│ ⭐ 高价值观点 (2)                  │
│  · 小明: "如果先看一个例子再讲理论..." │
│  · 周老师: "建议在难点前设一个认知锚点"│
└──────────────────────────────────┘
```

**实现**:
- 调用 LLM 分析最近 N 条消息
- 使用专门的总结 prompt 模板
- 结果以结构化 JSON 返回，渲染为卡片
- 卡片可展开/折叠，可收藏，可导出

### 6.4 角色事件触发器

**需求**: 系统定时或条件触发特殊角色事件

**事件类型**:

| 事件 | 触发方式 | 效果 |
|------|---------|------|
| 突然提问 | 随机/定时 | 学生角色突然提一个关于文档的问题 |
| 质疑挑战 | 检测到可争议点 | 家长角色质疑某个教学决策 |
| 补充案例 | 讨论进入瓶颈 | 老师角色分享一个相关教学案例 |
| 情感共鸣 | 检测到共鸣点 | 某角色表示"我深有同感"并展开 |
| 投票发起 | 随机 | 某角色对争议点发起投票 |
| 话题转移 | 空闲太久 | 某角色引导讨论转向未覆盖的维度 |

**实现**:
- `services/chatEngine/eventTriggers.ts` 定义各类触发器
- 每个触发器有触发条件（概率/时间/语义检测）
- 触发后生成 `RoleEvent`，经调度器放入事件队列
- Agent 以角色人设响应事件

## 10. 风险与注意事项

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 调用成本激增 | 热烈模式下每小时可达 10+ 次调用 | 清晰展示消耗预估，用户自主选择 |
| Agent 回复质量不稳定 | 讨论可能跑题或重复 | Prompt 严格约束 + 上下文窗口管理 |
| 延迟体验 | 多 Agent 串行回复导致等待时间长 | 打字指示器 + 合理延迟 + 流式输出 |
| localStorage 容量 | 大量聊天记录可能超限 | 消息分页加载 + 老消息压缩 |
| 跨分支合并冲突 | 两分支代码差异大 | 核心 engine 放在共享模块，分支只改业务适配层 |
